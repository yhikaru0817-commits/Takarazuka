# 宝塚ファンクラブ管理データ 整形ツール

チケット・お茶会/親睦会・グッズ・年間企画の各シートを読み込み、形式のばらつきを揃えて
「誰が・どのイベントで・いくら使ったか」を1つの形式にまとめます。

## 個人情報の取り扱い（重要）

- **すべてローカルPC上で処理します。** ネット通信は一切行いません。
- 実データは `data/raw/` に、出力は `output/` に置きます。どちらも `.gitignore` 済みで、
  `*.xlsx` / `*.csv` もリポジトリには入らない設定です。**実データを GitHub に上げないでください。**
- 画面には件数だけを表示し、氏名などは出しません。
- 顧客番号（`C00001` など）は連番なので、番号から個人情報は分かりません。配分システムには番号と金額だけを渡せます。
- テストは架空データのみを使っています。

## 使い方（いちばん簡単な方法）

1. **既存のシートを、形式がバラバラのまま `data/original/` フォルダに入れる**（Excel / CSV、1ファイルに複数シート可。
   シート名も列もそのままで大丈夫です）
2. **`整形する.bat`（Windows）/ `整形する.command`（Mac）をダブルクリック**
   - 初回だけ必要な部品を自動でインストールします（Python 3 が入っている必要があります）
   - ① 既存シートを指定の形式に整形 → ② 顧客マスター作成・統合 を続けて行い、`output/` フォルダが開きます
3. 画面に ★ が出たときだけ、次のファイルを直して保存し、もう一度ダブルクリック
   - 「★ 記入が必要なシート」→ `data/sheet_map.csv`（下の「既存シートの整形」参照）
   - 「★ 同一人物か確認が必要な組」→ `output/match_review.csv` の `decision` 列に **「同一」か「別人」**

人の手での作業は、機械が判断できなかったところに書き込むことだけです。書いた内容は保存され、二度と聞かれません。

## 既存シートの整形（`data/original/` → `data/raw/`）

1. すべてのシートについて、シート名・ファイル名・列から **種別・日付・名前を推測** し、対応表 `data/sheet_map.csv` に書きます。
   - 例: `渤海 宝塚大劇場 2026.1.21` → large / 20260121 / 渤海 → `2026_0121_大公演_渤海`
   - 例: `渤海お茶会参加者` → お茶会 / 渤海 → `渤海_お茶会`
   - 劇場名（宝塚大劇場・東京宝塚劇場・バウ・梅田・ドラマシティ・博多座など）や「お茶会」「親睦会」「グッズ」の語、
     日付（`2026.1.21`、`2026年1月21日`、`20260121` など）から判断します。
2. `sheet_map.csv` を開いて、**`note` 列に「推測」「確認」「記入してください」とある行だけ** 確認・修正してください。
   - `category`: `large` / `small` / `tea_party`(お茶会) / `social`(親睦会) / `annual` / `goods` /
     `post_sale`(事後販売：どの公演にも紐づけない) / `roster`(名簿：連絡先だけのシート) / `skip`(取り込まない)
   - `date`: `20260121` の形（公演・年間企画のみ必要）
   - `name`: 公演名・企画名（お茶会・親睦会・グッズは、紐づく公演と同じ名前にする）
   - 一度直した行はそのまま残り、次回以降も使われます。新しいシートを追加したときは、その行だけ追加されます。
   - **列名の行がないシート**は、`columns` 列に「各列が何か」の推測が入ります（例: `A=番号 C=名前 D=カナ E=電話 J=チケット K=サポート`）。
     A, B, C… は Excel の列です。違っていれば直してください。取り込まない列は書かないか `-` にします。
     使える名前: 名前・カナ・電話・メール・郵便番号・都道府県・住所1・住所2・チケット・サポート・参加費・合計・枚数・席種。
     値の形（メールの@、電話番号の桁、カタカナなど）からの推測なので、特に**金額の列（チケット／サポート）は必ず確認**してください。
3. 整形結果は、指定の列名・列順で `data/raw/<標準シート名>.csv` に出ます（確認用に `data/standardized.xlsx` にもまとめます）。
   - 電話・郵便番号・カナ・金額などの書き方はここで揃えます。タイトル行・合計行・空行は除きます。
   - 同じ公演が複数のシートに分かれていれば1つにまとめます。
   - 使わなかった列や気になる点は `data/standardize_report.csv` に出ます。
   - 列名が自動で判定できない場合は `config/column_aliases.example.csv` を `config/column_aliases.csv` にコピーして、
     `header`（元の列名）と `field`（`name_kanji` / `phone` / `ticket` / `support` など）を書いてください。

コマンドで実行する場合:

```bash
pip install -r requirements.txt
# data/raw/ に Excel (.xlsx) または CSV を置く（1ファイルに複数シート可）
python -m takarazuka_data            # 既定: data/raw → output
python -m takarazuka_data 入力フォルダ -o 出力フォルダ
```

**列名やシート名の確認だけしたいとき**（中身は表示されないので、相談用に貼り付けても安全です）:

```bash
python -m takarazuka_data --inspect
```

**相談用に「個人情報だけ架空の値にしたコピー」を作るとき**:
`相談用コピーを作る.bat`（Mac は `.command`）をダブルクリックすると、`data/original/` から `masked/` に作ります。コマンドの場合:

```bash
python -m takarazuka_data.mask      # data/raw → masked/
```

- 氏名・フリガナ・メール・電話・郵便番号・住所を架空の値に置き換えます。全角/半角、空白、ハイフン、先頭 0 落ちなどの書式のくせはそのまま残ります。
- 同じ人は同じ架空の値になります（名寄せの確認ができます）。毎回ランダムな鍵を使い、鍵は保存しないので、元の値には戻せません。
- 金額・席種・枚数・日付・都道府県・シート名・列名は残します。備考など用途の分からない列は「■」で伏せます。
- 送る前に必ず `masked/` の中身を開いて目で確認してください。

Google スプレッドシートの場合は「ファイル → ダウンロード → Microsoft Excel (.xlsx)」で保存してください。
CSV の場合はファイル名がシート名として扱われます。公式LINEから出力した申請CSVは
`2026_1105_大公演_星の詩_申請.csv` のようにファイル名を変えてから置いてください（文字コードは UTF-8 / Shift_JIS どちらでも可）。
LINEフォームの「希望枚数を入力してください」のような長い列名も、含まれる語（希望枚数など）で判定します。

## シート名の規則と分類

| 分類 | category | シート名 | 例 |
|---|---|---|---|
| 大劇場公演 | `large` | `年_月日_大公演_公演名` | `2026_0121_大公演_渤海` |
| それ以外の公演 | `small` | `年_月日_小公演_公演名` | `2026_0415_小公演_春の夢` |
| お茶会 | `tea_party` | `公演名_お茶会` | `渤海_お茶会` → large「渤海」に紐づけ |
| 親睦会 | `social` | `公演名_親睦会` | `春の夢_親睦会` → small「春の夢」に紐づけ |
| グッズ | `goods` | `公演名_グッズ` | `渤海_グッズ` → 同名の公演に紐づけ |
| 事後販売 | `post_sale` | `名前_事後販売` | `呂布_事後販売` → どの公演にも紐づけない |
| 年間企画 | `annual` | `年_月日_企画名` | `2026_1201_クリスマス会` |
| 今回のチケット申請 | `application` | `年_月日_大公演/小公演_公演名_申請` | `2026_1105_大公演_星の詩_申請` |

- 種別の書き方は `大公演 / 大劇場 / large` と `小公演 / 小劇場 / 別箱 / small` を受け付けます。全角・半角は問いません。
- 規則に合わないシート（`Sheet1` など）は取り込まず、`review.csv` に記録します。
- お茶会・親睦会の名前が公演名と違う場合は、`config/event_links.example.csv` を
  `config/event_links.csv` にコピーして紐づけ先を指定してください。

### シート名を標準の形にすると、設定が自動で決まります
元のシートの名前を、次の形に直しておくと、`sheet_map.csv` を手で直さなくても種別・日付・名前を正しく読みます。

| 種類 | シート名 | 例 |
|---|---|---|
| 大劇場公演 | `年_月日_large_公演名` | `2026_0404_large_呂布宝塚` |
| それ以外の公演 | `年_月日_small_公演名` | `2026_0121_small_雨にじむ渤海` |
| お茶会・親睦会・グッズ・事後販売 | `公演名_お茶会` など（先頭に `年_月日_` を付けても可） | `呂布宝塚_お茶会`、`2026_0125_雨にじむ渤海_親睦会` |
| 年間企画 | `年_月日_企画名` | `2026_0331_誕生日企画` |
| 名簿（連絡先だけ） | `名前_名簿` | `お礼状_名簿` |

- 公演名は、お茶会・親睦会・グッズが紐づく公演と**同じ名前**にします。
- シート名を変えると、古い名前の行は「元のシートが見つかりません」と記録されます。種別・日付・名前が同じなら、
  **古い行の列の指定（`columns`）を、新しい名前の行へ自動で引き継ぎ**ます（古い行は消えます）。

## 列名

`name(漢字) / name katakana / Family name / First name / mail / phone-number / post-number / prefecture / address 1 / address 2`
＋ 金額列（公演: `Ticket` `Support`、お茶会: `Entry_fee`、親睦会・年間企画・グッズ: `total_cost`）。

### チケット申請シート（今回分）

個人情報の列 ＋ `第1希望`（公演日時）/ `振替1` `振替2` …（振替日程）/ `枚数` / `席種` / `サポート代（見込額）`。

- 公演日時は `11/12(木) 15:00`、`1月5日 13時半`、Excel の日付などを読み取ります。年がなければシート名の日付から補います。
  公演日と開演時間が別の列（`公演日` と `開演時間`）でも可。
- 振替は複数列でも、1つのセルに `11/13 11:00、11/14 15:00` のように並べても可。
- 席種: large は `SS / S / A / B`、small は `S` のみ。空欄は申請時の既定（large: `SS`、small: `S`）。
- 席種ごとの価格は、過去の公演シートの「チケット代 ÷ 枚数」から自動で推定します（最も新しい公演の単価を採用）。
  推定結果は `seat_price_estimates.csv` に出ます。過去の単価が複数あれば `price_variants` に並ぶので確認してください。
  推定できない席種や、公演ごとに価格を指定したい場合は `config/seat_prices.example.csv` を `config/seat_prices.csv` にコピーして書いてください（こちらが優先されます。例の金額は仮の値です）。
- 申請のサポート代は**見込額**なので、過去の実績（spending / summary）には入れず、別の表に出力します。

過去の公演シートに `席種` `枚数` の列があれば、それも `ticket_history` に取り込みます。

よくある言い換えにも対応しています（例: 氏名・名前 / フリガナ / メールアドレス / 電話番号 / 郵便番号 / 住所 / チケット代 / 応援 / 参加費 / 合計金額 など）。
シートの上にタイトル行があっても、ヘッダ行を自動で探します。

## 自動で揃える内容

- 全角・半角、余分な空白
- フリガナ: ひらがな → カタカナ
- 電話番号: 数字のみ（Excel で消えた先頭の 0 を補完、+81 表記にも対応）
- 郵便番号: `123-4567` 形式（先頭 0 の欠けを補完）
- 都道府県: `東京` → `東京都`。空欄なら住所の先頭から取り出す
- 金額: `¥12,000円` → `12000`
- メール: 小文字に統一
- 「合計」行や空行は除外

### 名簿と金額のシートが分かれている場合
「名前・住所・電話」だけの名簿シートと、「名前・金額」だけのシートに分かれていても大丈夫です。
- 金額の列がなく連絡先があるシート（または名前に「名簿」「住所録」「会員一覧」などを含むシート）は `roster`（名簿）として、連絡先だけを取り込みます。
- 連絡先のない行（金額だけのシート）は、**同じ名前で連絡先のある人が1人だけなら自動で結びつけます。**
  同じ名前の人が複数いる場合だけ `match_review.csv` に出るので、「同一 / 別人」を書いてください。

## 同一人物の照合と顧客番号

### 自動で同一人物とみなす条件
**名前（漢字またはカナ）＋ 連絡先（メール・電話・郵便番号・住所・LINE ID のどれか）** が一致すること。

- 家族で電話や住所を共有していても別人として扱えるよう、連絡先だけでは結びつけません。
- 表記ゆれは吸収します: 全角/半角、空白、ひらがな/カタカナ、異体字（髙/高・﨑/崎・邊/辺 など）、
  住所の「1丁目2番3号」と「1-2-3」、電話・郵便番号のハイフンや先頭 0 落ち。

### 確認が必要な組（`output/match_review.csv`）
自動では結びつけなかったものの、同一人物かもしれない組だけが出ます。
- 「名前が同じで連絡先が違う」… 引っ越し・電話番号変更、または同姓同名の別人
- 「電話（住所・メール・LINE）が同じで名前が違う」… 家族、名前の誤記、改姓など

`decision` 列に「同一」か「別人」を書いて保存し（Excel で保存して大丈夫です）、もう一度実行すると反映されます。
空欄のままの組は次回も表示されます。判定は `data/master/match_decisions.csv` に保存されます。

### 顧客マスター（`data/master/customers.csv`）
- 顧客番号 `C00001`, `C00002` … を初登場の古い順に振り、**一度振った番号は変わりません。**
- 実行するたびに最新の連絡先・初回/最終参加日を反映します。上書き前に `data/master/backup/` へ自動でバックアップします。
- `line_id`（LINE のユーザーID）をシートの列に入れておけば照合に使われます。マスターに直接書き足しても構いません。
- `note` 列は自由メモ欄です（データで上書きされません）。
- `merged_into` に番号が入っている行は、その番号の人に統合済みです。

## 出力（`output/`）

| ファイル | 内容 |
|---|---|
| `events.csv` | イベント一覧。分類、日付、紐づけ先 (`linked_event_id`)、large/small/annual ごとの日付順通し番号 (`seq`) |
| `persons.csv` | 今回のデータに出てくる人の一覧（顧客番号・最新の連絡先・参加イベント数・新規かどうか） |
| `match_review.csv` | 同一人物か確認が必要な組（decision 列に「同一」「別人」を書く） |
| `spending.csv` | 1行 = 人 × イベント × 費目（ticket / support / entry_fee / total_cost）の金額 |
| `summary.csv` | 人ごとの分類別合計金額（公演はチケット代とサポート代を分けて集計） |
| `ticket_history.csv` | 過去公演の 人 × 公演（席種・枚数・チケット代・サポート代） |
| `application_requests.csv` | 今回の申請 1件ずつ（枚数・席種・サポート代見込額・チケット代見込み） |
| `application_preferences.csv` | 申請ごとの第1希望・振替の日時候補 |
| `seat_price_estimates.csv` | 過去データから推定した席種ごとの1枚価格 |
| `review.csv` | 要確認事項（不正な値、紐づけ不可、同姓同名など）。シート名と行番号付き |
| `formatted.xlsx` | 上記をまとめた Excel |

列の詳しい仕様は [DATA_SPEC.md](DATA_SPEC.md)（配分システムを作る方向け）を見てください。

```python
from takarazuka_data.pipeline import select_events
# 直近2回の large、直近2回の small、直近1回の annual と、それらに紐づくお茶会・親睦会・グッズ

```
